## 安装和第一次运行

1. 在 Chrome 安装并启用 Tampermonkey。
2. 打开 [最新版安装地址](https://7355608.site/userscripts/boss-ai.user.js)，按油猴提示安装；也可将本仓库 `dist/boss-ai.user.js` 的完整内容粘贴到油猴新脚本并保存。
3. 登录 BOSS，打开 [职位搜索页](https://www.zhipin.com/web/geek/jobs)，设置关键词及城市。
4. 点击右下角“AI 求职助手”，选择供应商，填写对应 Key、简历文字及求职偏好。“找实习”默认勾选，取消后找全职。
5. 点击“测试连接”，再“保存配置”。连接测试只发测试文字，不提交简历；正式任务使用已保存配置。
6. 初次使用保持“允许 AI 自动发送”关闭，点击“开始新任务”，先查看评分和招呼预览。试运行仍会读取职位、调用 AI 和打开脚本工作页，但不会点击沟通入口或发送消息。
7. 需要自动沟通时，先停止任务，勾选“允许 AI 自动发送”并保存，再启动任务。建议先把首聊额度设为 1，观察目标、实际文字、回执和记录，再提高额度。真实测试也计入额度。

面板顶部持续显示版本号和“收起”按钮，滚动到底部仍可收起。若更新后未生效，刷新 BOSS 页面并核对顶部版本。不要在脚本专用工作页中手动切换会话、输入草稿或发送消息。

脚本不显示时，检查油猴启用状态、站点访问权限和用户脚本执行设置，见 [Tampermonkey FAQ](https://www.tampermonkey.net/faq.php)。

## AI 配置与简历导入

仅使用 OpenAI 兼容的非流式 `chat/completions` 请求。以下公开地址和模型固定在 `src/core.js`，面板只读展示；请求自动追加 `/chat/completions`。

| 供应商 | Base URL | 模型 |
| --- | --- | --- |
| Qwen | `https://maas.qianwenaiapi.com/compatible-mode/v1` | `qwen3.8-flash` |
| DeepSeek | `https://api.deepseek.com` | `deepseek-flash` |

Qwen 选项使用上述用户指定服务的 Key，不要混用其它 Qwen 平台的 Key。模型能否调用取决于服务商及账号权限。切换供应商会清空 Key 输入框；旧配置地址与固定地址不同时，会清空 Key 并关闭自动发送。配置导入不能覆盖固定地址或模型。更换服务需修改源码配置及构建头部的 `@connect` 域名，再重新构建。

简历可手动粘贴，也可在停止任务后点击“导入简历并用AI整理”，选择文字版 PDF、DOCX、TXT 或 MD。原文件在浏览器本地解析，仅提取文字提交给所选 AI；整理结果校验原文依据后自动填入简历栏，核对后仍需点击“保存配置”。限制为 10MB、20 页 PDF、60000 字；不支持扫描件 OCR、加密 PDF 和旧 DOC。失败时保留原简历文字。这个导入功能与向招聘者发送附件无关，不修改 BOSS 上的简历。

“测试完整分析（不发送消息）”使用当前表单的简历、偏好和已读取职位，执行正式评分及招呼生成，不加入发送队列、不占首聊额度。短连接测试成功不代表完整分析一定及时完成。AI 等待上限默认 180 秒，可配置 30–600 秒；网络、响应及结果校验异常最多尝试 3 次，重试间隔为 1 秒、2 秒，连续失败后暂停任务。手动停止、到点或失去执行权会取消重试；不会因此重发已经点击发送的消息。

## 筛选、评分与招呼

| 设置 | 当前默认行为 |
| --- | --- |
| 城市 | 北京，依据职位地点字段；地点缺失转待确认 |
| 工作类型 | “找实习”勾选对应 BOSS 搜索网址 `jobType=1902`；取消对应全职 `jobType=1901`，不依据日薪或正文推断 |
| 匹配阈值 | 默认 80 分，通过城市条件后按代码加总分数判断；AI 的 suitable、uncertain 和疑点仅供展示 |
| 首聊额度 | 每个任务默认 50 次，包含待核实的发送预约；刷新保留计数，新任务重新计数，但保留历史去重 |
| 自动发送 | 默认关闭；开启后仍受运行时段、去重、额度、发送间隔和内容检查约束 |
| 类别轮换 | 默认开启，读取页面已挂载的类别入口，包括“更多”中的折叠项，按页面顺序点选，不手动填写名单 |

不再核对聊天窗口的岗位 ID 或名称，也不按招聘者或公司从列表自动选会话；首次发送直接使用沟通入口打开的聊天窗口。窗口未展开时等待最多约30秒后跳过该动作并交人工，其它岗位继续。输入框、历史去重及回执仍检查。详情页仍读取招聘者信息用于本地去重，这与已删除的聊天窗口岗位比对是两个环节。

AI 返回各分项分数，代码校验范围并求和，总分保留一位小数：

| 分项 | 满分 |
| --- | ---: |
| 核心技能与工作内容 | 30 |
| 项目经历与可迁移能力 | 20 |
| 基本任职条件 | 20 |
| 求职偏好 | 20 |
| 加分项与优先条件 | 10 |

“加分项”“有相关经历者优先”等非必需条款仅影响最后 10 分，不能因同一缺口在其它分项重复扣分；没有加分条款时该项按 10 分中性计入。充分匹配的分项参考满分的 90%–100%，大部分匹配 75%–89%，部分匹配 50%–74%，明显不匹配 0%–49%。城市与工作类型不重复计分。评分由 AI 判断，不能视为招聘者的客观评价。

首条招呼优先生成 100–180 字正文，介绍 1–2 项真实经历、用到的技术及实际工作。缺少高度相关经历时选择可迁移经历，不编造职责、项目、年限或成果。代码核对简历原文摘录；依据不足时丢弃原招呼，改用真实简历片段或中性招呼并继续。原文检查不能保证生成文字完全无误，首次使用应查看预览。

对外文字使用“我”“本人”“您”等代称；代码会替换可识别的本人及招聘者姓名，非结构化姓名仍依赖模型遵循提示。招呼追加以下介绍及项目链接，介绍不计入正文的优先字数范围：

> 此消息发送自本人开发的油猴插件，这是一个基于大模型的求职助手，可分析岗位匹配度并自动发送个性化打招呼。
>
> 自动发送项目：https://github.com/Ru1BB/Boss_ZP_Job_Finder

不再强制追加旧尾注“（本消息由 AI 发送）”。旧尾注仅用于兼容历史去重和清理旧待发内容。

## 运行节奏、定时与遍历

| 面板设置 | 默认值及含义 |
| --- | --- |
| 招呼发送最小间隔 | 180 秒，可在面板调整；用于首次文字招呼，跨任务保留 |
| 共用随机延迟最小／最大 | 10／60 秒，每次独立抽取整数；也用于刷新和岗位扫描 |
| 打开职位前等待 | 基础 0 秒，加一次共用随机延迟 |
| 填入招呼前等待 | 基础 0 秒，加一次共用随机延迟 |
| 填入后多久点击发送 | 基础 0 秒，加一次共用随机延迟 |
| 多久处理下一个岗位 | 读完并处理职位后安排下一次岗位扫描，基础 0 秒加一次共用随机延迟 |
| AI 请求等待上限 | 180 秒，范围 30–600 秒 |

四项动作基础等待范围均为 0–3600 秒。实际等待为“基础秒数＋本次随机秒数”，例如基础 5 秒、随机 10–60 秒，实际为 15–65 秒。共用范围不表示所有动作使用同一个抽样值；连续抽到相同值也可能发生。原有最小发送间隔仍独立生效，网页加载、AI 分析和其它动作会额外增加实际耗时。

工作页在填入或发送等待阶段被刷新时，取消该次动作并交人工核对，不重新点击沟通或发送。等待中检查停止、时段及执行权；填入和发送前重新检查聊天记录，草稿或会话变化时取消当前动作。工作指令时限包含已抽取的填入和发送等待预算。

定时默认关闭，使用北京时间每日一个可跨午夜时段。启用、配置并保存后，保持已登录的 BOSS 搜索页和电脑运行，到开始时间可自动新建任务，无需先点开始；运行中的任务不重复启动。到点停止会取消排队操作，手动停止后本时段不自动重启。关闭浏览器、休眠或后台冻结可能导致定时延迟，恢复后过期动作不补发。未启用定时的手动任务需手动停止。

按岗位 ID 跳过未隐藏且已有有效评分的记录，包括 0 分；新任务也不重复评分。明确获准重新评估的记录例外。搜索耗尽后轮换页面类别，无法切换则刷新搜索页继续同一任务；刷新保留已读岗位、计数及去重。达到首聊额度后不再发起新首聊，但仍可扫描及仅打开不匹配岗位，直到停止。

“不匹配岗位也仅打开沟通”默认勾选，但需同时开启自动发送并勾选“我已实测确认当前 BOSS 设置点击立即沟通不会自动代发默认招呼”才生效。仅点击沟通入口，不填写或发送文字，不启动该会话自动回复；每岗位只尝试一次，不计首聊额度、不等待或更新统一发送间隔。此功能仍按扫描节奏串行运行，不能保证平台从搜索结果移除该岗位。平台会代发默认招呼时不要勾选确认。

## 首聊去重与发送回执

本地已发送、进行中预约及未解除的待核实记录阻止同一招聘者同一岗位重复首聊。聊天中已有旧 AI 尾注或当前插件介绍的本人消息，也会阻止重复首聊。已有人工消息、平台默认招呼、招聘者消息或未知卡片时，不追加首次招呼，交由人工核对。

已识别的“你与该职位竞争者PK情况”平台卡片不进入对话历史；仅在结构、标题、按钮及无附加真实内容均符合时忽略。已知附件发送成功系统通知也从对话历史中排除，避免方向未知导致读取中断；这不代表脚本会自动发送附件。头像与真实图片区分处理，不将头像误判为图片消息。

后续私信全部由人工处理，脚本不巡检已联系对象、不生成回复、不处理简历请求或招聘者卡片。旧版配置中的回复上限等字段不再生效，旧版待回复及相关重试队列会被取消；已有发送不明确的记录仍保留待核实，避免重放。

首次招呼不比对聊天岗位，保留历史去重、草稿保护及消息回执。详情页仍读取招聘者信息建立去重记录，聊天页不再按姓名、公司、岗位 ID 或标题核对目标。

0.1.41 的回执检查在点击发送后最多读取 12 次，每次等待约 400 毫秒。找到同时满足以下条件的消息，即将本次动作标记为“确认发送”：

1. 消息 ID 在点击发送前的记录中不存在。
2. 消息方向为本人外发，且为文字内容。
3. 正文与本次实际发送文字一致，仅归一化空白和零宽字符；优先提取 `.text-content`，排除“已读”等状态文字。

不再仅凭“AI”关键词或任意新增非空消息确认。未找到对应消息时标为发送待核实，不自动重发。首聊发送成功验证该次发送，不代表所有页面与长期运行场景均已通过验证。

对于误标的首聊，先停止任务并等待当前操作退出，人工确认会话确实未发送后，再点“我已核实未发送，重新评估”。它只记录确认，之后重新读取和评分，不立即发送、不退还额度、不清零发送间隔，也不能解除本地已确认发送记录。

## 日志、异常与工作标签页

“清空日志与待处理”停止任务、取消排队动作并清空可见日志和待处理列表；内部保留已联系、已有沟通、发送待核实及发送历史用于去重，也保留 Key、配置、任务计数和发送间隔。**累计统计仍会统计保留的内部记录，清空后不一定归零。** 清空不会撤回已发消息，也不会在本定时时段自动重启。

临时职位或首次沟通窗口加载故障最多延后重试两次，间隔 60 秒、120 秒，三次失败后标记对应对象待人工。只有明确尚未打开沟通、未填草稿、未点击发送的预约可沿用原预约重试，不再占额度；已打开沟通、已填草稿或发送状态不明的动作不自动重放。AI 异常另按最多 3 次尝试处理，连续失败暂停任务。

验证码、登录失效及平台限制会先短暂复核；只对只读操作的临时加载问题尝试有限恢复，不绕过验证。持续限制、执行页面全局异常或工作页关闭无法确认会暂停，需要人工处理。

每个指令使用脚本创建的临时工作标签页，完成或失败后关闭；主页面确认旧页关闭后才开下一页。不会关闭用户手动页面。提示旧工作页未关闭时，可先停止任务，手动关闭残留页，再用“清理残留工作页”核对；仍存在的工作页不会仅凭旧心跳被强行认定已关闭。

一个搜索页持有主执行租约，工作页也有独立租约，避免多标签重复执行。刷新或接管后只读中断可恢复；发送中断则根据已保存阶段判断未发送或待核实，不盲目重放。

无页面操作或 AI 请求时，每 30 分钟维护数据：每次最多移除 500 项、7 天前的过期临时标记和租约，保留当前执行及未确认发送证据；30 天前已结束且非待核实的发送记录仅精简正文，不删除去重标识和配置。面板显示累计数量及最近清理时间。

## 页面诊断和验证方法

停止任务，在右侧已展开的目标会话中运行“只读诊断当前页面”，核对容器、岗位、输入框、发送按钮及消息数量。高级适配仅接受选择器、属性名和验证标记，不执行任意 JavaScript；不要仅修改验证标记就认为页面流程已验证。

开启并保存“调试模式”后，左下角出现“调试：获取聊天页面信息”，可采集、复制或下载诊断 JSON。诊断只读，不调用 AI、不点击平台按钮、不发送消息，也不会自行停止正在运行的任务，建议先手动停止。

报告包含容器和控件结构、位置、消息 ID 是否存在或重复、方向、正文长度、头像及富媒体结构和异常提示。默认不含消息正文、草稿、Key、简历和完整 URL；勾选“包含最近消息正文”后重新采集，仅本次包含最近 20 条已加载消息的预览，每段最多 500 字。报告可能含私人聊天内容，分享前检查。它不代表账户全部消息，也不能单独证明消息由脚本还是人工点击发送。

真实验证可把首聊额度设为 1，启动后不手动输入或点击发送，核对目标和正文只出现一次，再对照诊断与“已确认首条招呼发送”记录；刷新后检查去重。后续回复由人工操作，无需验收自动回复流程。

## 隐私与运行边界

- Key、配置和运行记录保存在油猴存储；Key 遮罩显示，不写入源码、日志或导出文件。本地存储不等于加密保险箱。
- 配置导出不含 Key，但包含简历和偏好；导入清除 Key、自动发送权限及流程验证标记，仍需核对并保存。
- AI 接收所选供应商所需的简历、偏好、职位文字；首次招呼的本地聊天读取用于去重与回执，不再提交聊天历史给AI；不提交职位安全查询参数、BOSS Cookie 或页面控制字段。职位与聊天只作为待分析数据，不能覆盖固定系统规则。
- 只通过 DOM 操作 BOSS 页面和油猴跨域请求调用 AI，不使用未公开 BOSS 接口或外部 CDN 脚本。
- 不自动确认面试、接受 offer、承诺薪资、交换联系方式或绕过验证码。平台限制及页面改版可能影响运行；间隔和额度不能保证平台允许自动化。使用前阅读 [BOSS 用户协议](https://www.zhipin.com/web/common/protocol/protocol-2019-09-30.html)。

## 开发、测试和发布

技术栈为原生 JavaScript、Shadow DOM 面板、Tampermonkey 存储／跨域请求／标签页接口，以及 OpenAI 兼容 Chat Completions。没有使用 LangChain、向量数据库或 RAG；简历、偏好及必要上下文直接提交给模型。PDF.js、fflate 随脚本打包，用于本地简历解析。

| 文件 | 作用 |
| --- | --- |
| `src/core.js` | 配置、评分、去重、调度、发送规则与回执比较 |
| `src/adapter.js` | DOM 读取、聊天可用性检查、输入框操作及页面诊断 |
| `src/app.js` | 面板、AI 请求、主任务、租约、等待和工作页调度 |
| `src/resume-reader.entry.js` | 本地 PDF／DOCX／TXT／MD 简历提取 |
| `scripts/build.cjs` | 打包完整脚本及更新元数据 |
| `dist/boss-ai.user.js` | 可安装的单文件脚本 |
| `dist/boss-ai.meta.js` | 油猴更新检查元数据 |
| `test/` | 业务规则、适配器、运行时、工作页及发布测试 |

开发需要 Node.js 22.13 或更新版本：

```powershell
npm ci
npm run build

```
