# BOSS AI 求职助手

Chrome + Tampermonkey 油猴脚本。通过悬浮面板选择供应商、填写 Key、简历、求职偏好、时段和间隔。两组 Base URL 与模型已固定在代码中，不需要编辑源码或部署服务器。项目目录与全部控件说明见 [PROJECT_GUIDE.md](PROJECT_GUIDE.md)。

**当前交付仍未完成真实发送验收。** 已只读核对 BOSS 搜索页和详情页，并依据用户提供的聊天页面诊断更新头部、岗位卡片和消息字段。尚未通过本项目的实站验收向真实招聘者发送消息或简历。自动发送默认关闭，勾选并保存表示授权，执行时仍核对对象、输入框和回执。单元测试通过不等于实站发送验收通过。

当前版本 0.1.17：新增“核对聊天窗口”开关，旧配置默认开启。停止任务后取消勾选并保存，可跳过聊天岗位 ID/名称核对，使用当前已打开的会话，可能发错对象；不会跳过聊天已展开、唯一输入框、历史去重、草稿校验、停止信号、额度及间隔检查。详情页目标按钮绑定和会话选择仍保留；回复及附件同样受此开关影响。读取岗位卡片时兼容缺少内层 position-content 的布局。以下岗位核对规则适用于开关开启时。面板顶部和工作标签页显示版本号。聊天编辑器改用原生插入文字流程（不支持时使用保留换行的 innerText），统一草稿读取及换行、不换行空格校验，最多额外等待 500ms 同步，不重写草稿或重试发送。其它字符不一致仍停止。尚未完成实站发送验收。聊天有岗位 ID 或唯一岗位链接时核对 ID；没有 ID 时仅核对岗位名称，名称一致即通过这项检查，不要求薪资、城市、招聘者或公司完整或一致。不再因已读取的其它岗位同名而阻止通过。岗位名称只规范 Unicode 和空白，不做模糊匹配；缺失或不一致时停止。详情沟通按钮仍需绑定目标岗位。仅凭名称可能混淆不同公司的同名岗位。重复发送、发送状态不明、权限、额度及间隔检查继续生效；搜索阶段的北京实习筛选不变。

进入空白消息页后会按公司及招聘者唯一选择目标会话，等待加载，再核对岗位，不重复点击“立即沟通”。同一身份的嵌套头部会去重，冲突身份仍停止。旧默认选择器自动迁移，自定义选择器保留。首次招呼要求排除已识别的系统卡片后，会话中没有消息；若已经有真实消息、未识别卡片或平台代用户发送的默认招呼，会停止追加，需人工核对。

“你与该职位竞争者PK情况”系统卡片会被忽略：必须同时匹配收入方向、蓝色卡片结构、完整标题和“查看详细分析”按钮，且没有卡片之外的文字或媒体。它仍显示在网页上，但不进入聊天历史、不提交给 AI、不阻止首条招呼，也不因单独出现而触发回复。其它卡片、普通文字引用同名标题、招聘者消息和自己发出的招呼不会被忽略。只读诊断中的 `messageSummary` 分别显示可见行数 `visibleRows`、忽略系统卡片数 `ignoredSystemCards` 和剩余消息数 `conversationRows`；原 `counts.messages` 仍是原始 DOM 行数。

## 安装和第一次运行

1. 在 Chrome 安装官方 Tampermonkey。进入油猴控制面板 → 添加新脚本。
2. 把 `dist/boss-ai.user.js` 的**完整内容**替换到新脚本编辑器并保存。
3. 登录 BOSS，打开 `https://www.zhipin.com/web/geek/jobs`，手动设置城市为北京、岗位类型为实习及关键词。
4. 点击右下角 **AI 求职助手**。选择供应商，地址和模型会自动显示；填写对应服务商的 Key、简历文字和偏好。
5. 点击 **测试连接**。这个动作只发送测试文字，不发送简历；成功后点击 **保存配置**。
6. 保持 **启用自动发送**关闭，点击 **开始新任务**。脚本只读职位，展示判断与招呼预览。首次会打开专用工作标签页，不要在该标签页手动切换会话、输入草稿或发送内容。
7. 如果页面结构无法读取，先停止任务，用 **页面诊断与高级适配**校准。缺少可靠字段时不会猜测，也不会自动发消息。

如果脚本没有出现在页面上，先检查油猴是否启用此脚本、站点访问权限和当前 Chrome/油猴的用户脚本执行设置，参考 [油猴官方 FAQ](https://www.tampermonkey.net/faq.php)。不要把 API Key 发到聊天里或截图中。

## AI 接口配置

仅支持 OpenAI 兼容的非流式 `chat/completions` 和 JSON 输出。0.1.2 起按用户要求固定下面两组公开配置，面板只读展示，API 请求会自动追加 `/chat/completions`。Key 仍只在面板填写，不写入源码。

| 供应商 | 固定 Base URL | 固定模型 |
| --- | --- | --- |
| Qwen | `https://maas.qianwenaiapi.com/compatible-mode/v1` | `qwen3.8-flash` |
| DeepSeek | `https://api.deepseek.com` | `deepseek-flash` |

Qwen 选项使用用户指定的 `qianwenaiapi.com` 服务，需要填写该服务商的 Key；不要与其它 Qwen 平台的 Key 混用。DeepSeek 的接口格式参考 [官方文档](https://api-docs.deepseek.com/api/create-chat-completion/)。模型 ID 按用户指定值固定，仍需账号实际拥有调用权限；连接或响应结构异常时任务暂停，不自动换供应商、不自动重试发送。

油猴元数据 `@connect` 包含这两个确切的服务域名，不需要开放全域访问。若未来需要改接口，应修改 `src/core.js` 中的 `PROVIDERS` 和构建头部的域名权限，再重新构建；配置导入无法覆盖固定地址和模型。

切换供应商会清空 Key 输入框，请重新填写并保存。升级时若旧接口与新的固定接口不同，会清空有效 Key 并关闭自动发送；其它设置仍保留。测试连接使用当前表单，实际任务使用已保存配置。

### 连接正常但完整分析超时

短连接测试只请求 `{"ok":true}`，并严格检查 `ok === true`，不提交简历。正式分析提交简历、偏好、评分规则和必要职位文字，还要生成评分、理由、招呼及原文依据；短请求通过不证明完整分析能够及时完成。请求采用非流式模式，代码收到完整响应后才解析。

旧版客户端固定60秒等待上限，较慢的完整分析可能被主动中断。现在在 **运行与间隔 → AI 请求等待上限 / 秒** 设置，默认180秒、范围30–600秒，旧配置自动补入默认值。油猴传输超时和独立计时器使用同一值；超时先记录原因再取消传输，避免取消回调覆盖“超时”。面板显示当前请求类型、已等待秒数、上限和请求正文字符数，不记录 Key 或正文。字符数不是 token 数。服务商端可能有自己的限制，延长客户端上限不保证解决上游超时；超时后暂停，不自动重试。

停止任务后点击 **测试完整分析（不发送消息）**，会用当前表单中的简历、偏好和最近已读取的完整职位（详情页则读当前职位）调用与正式任务相同的分析函数，展示耗时、评分和招呼，不加入发送队列、不占用首聊额度。没有职位数据时，可先试运行读取一个职位并停止，或在详情页测试。完整测试会将上述资料提交给所选供应商；结果含简历相关文字，分享前核对。测试成功后仍需 **保存配置**，再开始新任务。

AI 只收到职位 ID、标题、描述、类型、城市、薪资和公司等必要职位字段，不提交职位 URL、安全查询参数、招聘者内部 ID 或页面控制字段。响应解析区分错误响应、空正文、输出截断和 JSON/评分结构不符；这些情况不会当作成功，更不会直接发送未经校验的文字。改动经过模拟响应测试，真实服务响应速度仍需在自己的账号上通过完整分析测试验证。

网络错误会显示目标域名及已知的错误类别，不显示原始请求日志。HTTP 401 表示认证失败，404 表示接口路径或模型不存在，429 表示频率/额度限制；网络层没有 HTTP 状态时，不能据此断言 Key 或模型有误。

## 默认行为

| 设置 | 默认值 / 含义 |
| --- | --- |
| 必需城市 | 北京；仅依据职位地点字段判定 |
| 必需类型 | 标题、岗位类型或正文包含“实习”，或专门薪资字段显示日薪，二者满足其一即按实习处理；即使类型写了全职，明确日薪也通过该项过滤 |
| 信息不足 | 未找到实习文本且不是明确日薪 → 待人工确认，明确非实习类型则排除；地点不明也待确认，不根据正文偶然出现的“北京”推断地点 |
| 匹配标准 | 通过北京/实习等必需条件后，AI 分数达到配置阈值（默认 80）即进入待发送；suitable、uncertain 和疑点仅展示，不参与拦截 |
| 首聊额度 | 每个新任务最多 50 次，含发送结果待核实的预约；手动点击新任务重置额度 |
| 对外发送间隔 | 至少 180 秒；首聊、后续回复和简历共用一个计时器，跨任务保留 |
| 刷新随机等待 | 每轮独立从 10–60 秒整数中抽取，可以在面板调整上下限 |
| 自动回复上限 | 每个会话每任务最多 5 条文字回复；达到后转人工 |
| 定时 | 默认关闭；北京时间每日一个时段，支持跨午夜 |
| 附件简历 | 明确索要时发送预先指定的唯一 BOSS 附件简历，不读取本地文件 |
| 核对聊天窗口 | 默认开启；停止任务后取消勾选并保存，跳过岗位 ID/名称比对，使用已打开的会话，可能发错对象；仍保留输入框、历史、内容、停止、额度和间隔检查 |
| 允许 AI 自动发送 | 默认关闭，试运行不点击“立即沟通”、发送消息或发送简历；勾选并保存后授予发送权限，实际发送前仍核对对象；取消勾选立即撤销，已发送内容不能撤回 |
| AI 发送标注 | 所有 AI 首条招呼和自动文字回复末尾强制添加“（本消息由 AI 发送）”；预览与实际发送一致，不修改简历文件本身 |

“随机刷新”是在读完一个职位后随机等待，再刷新**主搜索页**，继续处理未读取职位；没有新职位时按同样的随机等待进行翻页或滚动。网页加载、油猴执行标签页选举和模型响应时间另计，所以实际刷新间隔可能更长，不承诺每隔精确的 10–60 秒刷新。随机抽样可能碰巧连续抽到同一个数值，但没有固定周期。随机等待用于运行节奏，不用于绕过平台限制。

每个任务保留已读岗位、发送预约和队列，刷新不会重置计数。同一招聘者同一岗位的本地已确认发送记录、进行中预约、未解除的待核实记录会阻止重复首聊；聊天中已有带 AI 标注的外发消息也会阻止重复首聊。标注只认外发方向，不把招聘者引用该文字当作已发送。人工消息和平台代用户发送的默认招呼仍转人工，避免突然插入另一段自我介绍；已识别的 PK 系统卡片不算聊天消息。不仅凭当前可见窗口里“没看见标注”推断从未发过，因为历史消息可能没有加载完整。

## 评分及经历介绍

AI 按简历给分项分数，代码检查范围并求和，总分保留一位小数；不采用模型另报的总分。0.1.13 起提高求职偏好权重，并保存每次分析使用的分项满分。旧记录不会改写：原分项记录会注明“旧权重”并按旧满分显示，早期无分项记录注明“旧版综合评分”。更新后请停止旧任务、替换脚本并刷新，再开始新任务。

按职位 ID 检查“职位、招呼与待处理”中未隐藏的评分记录；已有有效评分的职位直接标记为本任务已读，跳过详情页和 AI 调用，手动新建任务也不重复评分。0分也是有效评分；未评分或已清空/隐藏的记录不触发此项跳过规则。明确点击过“我已核实未发送，重新评估”的记录仍可重评。若想用新权重分析未联系的旧岗位，可先清空日志与待处理；内部已发送/待核实记录仍保留去重保护，不能靠清空重复发送。

| 分项 | 满分 | 判断依据 |
| --- | ---: | --- |
| 核心技能与工作内容 | 30 | 完成核心工作的技能基础 |
| 项目经历与可迁移能力 | 20 | 相关项目、实际做过的工作及可迁移经验 |
| 基本任职条件 | 20 | 明确必需的学历、专业、年级、可实习时长等 |
| 求职偏好 | 20 | 用户填写的方向等偏好 |
| 加分项与优先条件 | 10 | “加分项、有相关经历者优先、有则更佳”等非必需条款 |

“优先”条款只影响最后10分，不因缺少同一项经历在其它维度重复扣分；若另一条款明确将该技能列为必须，按必需条件评价且不重复扣分。没有任何加分条款时，最后一项按10分中性计入。核心四项合计80分、加分项0分，总分仍是80分，可达到默认阈值。

各项充分匹配可得该项满分的90%–100%，大部分匹配75%–89%，部分匹配50%–74%，明显不匹配0%–49%。分项判断仍由 AI 作出，不是招聘者的客观评定；未提及不等于已掌握，也应与明确不满足区分，并列入疑点。北京和实习由前置过滤处理，不重复扣分。只有总分是否达到用户阈值决定 AI 筛选结果，适合/不确定标记仍只作参考。

首条招呼优先100–180字，介绍1–2项与岗位相关的真实经历，说明做过什么、使用的技术和实际承担的内容。没有项目经历时可以介绍已有技能或学习经历，不补造项目、职责、规模、成果数字或年限，不把 AI 辅助开发扩写为模型训练、Agent/RAG 工程经历。模型必须返回1–3条简历原文摘录，代码核对摘录确实存在；这项检查不能完全证明整段生成文字都由摘录支持，预览仍保留供核对。个人姓名禁用及 AI 发送标注规则继续生效。

0.1.4 修复多搜索标签页下任务未启动却一直等待执行权的问题：空闲时，点击“开始新任务”的页面会申请执行权并自动启动；已有任务运行时不能抢占，需先停止。状态栏会区分“就绪”和“其他标签页执行中”。

0.1.5 修复只读取 `data-boss-id` 导致无法识别当前招聘者的问题：兼容招聘者区域其它 ID 属性和链接；平台 ID 不存在时，以公司和招聘者可见信息建立明确标注的本地身份记录；当前聊天发送核对规则见顶部 0.1.17 说明。平台 ID 冲突不会绕过检查。当前详情页的沟通按钮需要绑定本岗位 `jobId`，才可自动进入沟通；没有绑定信息的旧结构仍需要人工验证。发现平台已发默认招呼时不追加第二条。

0.1.6 按用户要求简化 AI 筛选：满足必需条件、分数达到阈值就进入发送队列，不再要求 AI 的“适合”或“没有不确定性”标记。模型仍输出理由和疑点供查看，并必须生成非空招呼；达到阈值不代表立即发送，实际动作仍受自动发送权限、对象核对、有效内容、运行时段、发送间隔、去重及额度控制。

面板新增 **清空日志与待处理**：点击后先停止任务并取消尚未执行的操作，清空日志与可见待处理列表；后台工作页独立退出，不需要等关页结束。已联系、已有沟通、待核实及发送历史在内部保留，用于去重；已有会话的排队回复被取消，已处理记录从列表隐藏。不会清空 Key、简历、求职偏好、任务计数、发送间隔或已读岗位记录，不会撤回已发消息。清空后不会在本定时时段自动重启，需要手动开始新任务；未来新消息或新任务生成的记录可以再次显示。

0.1.7 修复清空长期停在“正在停止任务并清空”的问题：非搜索页可临时取得仅用于清理的执行权，无需保持搜索页打开；任务停止后，不再等待本页 AI 请求、读页、关页或启动流程全部退出才清空。清理完成后释放临时权限，仍只允许从搜索页开始任务。清空同时取消正在等待的启动请求，避免它在清理结束后重新启动任务。跨标签页的运行中任务仍通过停止指令与执行租约协调处理。

每个读取/沟通指令使用一个临时工作标签页，完成或失败后先存结果再关闭；主搜索页通过油猴标签元数据和关闭句柄确认它已关闭，才允许开下一页。旧页关不掉就暂停，不因心跳超时反复开新页。停止和过期指令也会触发工作页关闭。只关闭脚本标记的页面，不关闭主搜索页或用户手动页面。更新到这一版本时请先手动关闭旧版本遗留的工作页，因为它们没有新的标签标记。

AI 招呼和回复新增“不出现个人姓名”的固定指令，使用“我/本人/您/您好”等代称；代码还会将简历中“姓名：…”字段及当前招聘者姓名从待发送文字中替换。公司、学校和技术名称可保留。不修改附件简历内容；无法从无结构简历中识别的名字仍依赖模型遵循指令，初次使用应核对预览。

遍历结束、连续三轮滚动仍无新职位，或首聊额度耗尽后停止找新职位，已有会话仍可处理到停止时间。手动停止后，本定时时段不自动重启；次日新时段可以新建任务。没有启用定时的手动任务需手动停止。

## 页面校准与真实发送验收（尚未完成）

这一节是**使用前的待办**，不是已通过的验收记录。不要只把 `verified` 改为 `true` 就运行。BOSS 页面可能改版，默认模板中的一些属性可能根本不存在。

1. 在实际搜索、详情和聊天页点击 **只读诊断当前页面**，查看匹配元素数量。点 **载入默认适配模板**会把完整 JSON 放入表单，修改后保存。仅支持 CSS 选择器和属性名，不执行自定义 JavaScript。
2. `card/cardLink/detail/title/employmentType/salary/city`：分别匹配搜索卡片、卡片内详情链接、职位正文、标题、类型、薪资和工作城市。实习文本或明确日薪满足其一即可；日薪只读取专门薪资字段，不把正文里的日餐补当日薪；城市必须来自专门地点字段。
3. `recruiter/recruiterAttr`：优先读取稳定的平台招聘者 ID；详情页缺少 ID 时使用公司和招聘者可见信息建立本地去重记录；聊天页发送前仅核对岗位，姓名不能单独作为发送依据。`recruiterScope/recruiterName/company`配置详情页身份，`chatHeader/chatRecruiterName/chatCompany`配置聊天页对应区域。没有岗位链接的卡片使用 `chatPosition/chatTitle/chatSalary/chatCity`，仅按岗位名称和详情按钮绑定核对。只读诊断会报告来源缺失或互相冲突，不把安全令牌当作招聘者 ID。
   会话列表支持 `conversationRow/conversationName/conversationCompany`，仅在公司与招聘者均精确且唯一匹配时选择；列表选择不是发送授权，选择后仍核对当前岗位。`chatEmpty` 匹配空白会话占位提示；等待超过30秒会结束该操作。诊断新增聊天容器、身份字段、空白占位数量和 DOM 结构摘要，摘要不包含聊天正文或属性值；请在右侧已展开的真实会话中运行诊断。
4. `messages/messageIdAttr/messageIncoming/messageOutgoing/messageText`：每条消息要有稳定且唯一的 ID、唯一方向和准确正文。不明确时会暂停，不将媒体内容提交给 AI 代猜。
5. 当前详情页支持读取沟通按钮的本岗位目标标识；发送权限开启后会先核对详情及目标再点击。没有明确岗位绑定的其它页面，只有人工验证流程后才可用 `verifiedContact` 和 `firstContactOpensEmptyChat`兼容。若平台自动发了默认招呼，脚本会阻止追加 AI 招呼并转人工，不保证能覆盖平台自带招呼。
6. 普通文字沟通由运行时核对当前会话、消息 ID、输入框及发送回执，不再以 `verifiedReply`静态标记作为授权开关。先用你指定的会话少量测试，不要把测试通过当成所有页面都可兼容。
7. 附件流程必须是**打开列表 → 按完整名称选择唯一文件 → 明确点击发送按钮 → 附件回执**。确认选择文件本身不会发送，并校准 `resumeOpen/resumeDialog/resumeItem/resumeName/resumeSend/resumeReceipt`后，才设置 `verifiedResume: true`。无法唯一识别附件或回执时转人工，不从候选列表随便选择。
8. 停止任务，勾选“允许 AI 自动发送”并保存。首次只把额度设为 1，核对实际消息、对象、简历和记录后，再提高额度。真实发送测试也计入额度。

后续回复只处理脚本已联系的会话；面试、时间确认、到岗、薪资协商、联系方式、验证、付款、链接/安装等敏感事项或媒体消息转人工。AI 文字回复需要引用简历/偏好中的逐字依据；这是降低编造概率的检查，不能保证 AI 完全正确。发送前重新核对会话、未回复消息 ID 和输入框内容，不覆盖已有草稿。简历只响应明确索要，“不用发简历”等否定表述不会触发。

发送阶段会单独持久化：预约/准备、打开会话、填写草稿、进入点击发送、回执确认。明确在消息发送前中断的首聊显示“发送前中断，待重新评估”，并保留具体错误；已进入点击发送或旧版缺少阶段证据的记录仍显示“发送待核实”，不自动重试。上述阶段不能证明 BOSS 的“立即沟通”是否代发了默认招呼，因此恢复时仍重新读取聊天内容。

针对误标的单个首聊，可在执行搜索页**停止任务并等操作退出**，人工核对会话全部历史、确认确实没有发出招呼后，点击该记录的 **我已核实未发送，重新评估**。按钮记录人工确认，不会立即发送、不退还已占用额度、不重置发送间隔，也不能解除本地已确认发送或已发现 AI 消息的记录。开始新任务后重新读取、评分和核对会话；已建立联系的页面直接打开会话，不重复点“立即沟通”。若仍有真实消息/未知卡片或发现 AI 标注，继续跳过并说明原因。收到新消息导致旧草稿过期时，任务会暂停，草稿留待人工处理。

## 存储、停止和限制

- Key、配置和运行状态位于油猴存储，Key 用密码框展示，不写入源码、日志或配置导出；本地存储不是加密保险箱。导出文件**仍包含简历与偏好**，分享前自行删除个人资料。导入会清除 Key 和所有发送验证标记，且不自动保存或启用发送。
- 不上传 BOSS Cookie、不请求未公开的 BOSS 接口、不使用 CDN 脚本；AI 调用发送你配置的简历、偏好、必要岗位和最近会话文字。
- 一个搜索页持有执行租约，每次指令的临时工作页完成后关闭，重复标签页通过独立租约避免同时执行。刷新后可能要等旧租约到期（约 15 秒），避免两个页面同时行动。
- 发送前持久化预约和执行标记；点击后回执不明、刷新中断、验证码、登录失效、平台限制或页面异常都会暂停，不盲目重发。已经点击发出的操作不能撤回。
- 到停止时间或点击立即停止后，所有尚未执行的动作失效。电脑休眠、关闭浏览器或标签页冻结期间不能保证定时启动；恢复后先核对时段，过期不补发。
- 不自动确认面试、接受 offer、承诺薪资、交换联系方式或处理音视频。不要关闭平台风控或尝试绕过验证码。
- 自动化可能违反平台规则或触发账号限制；设置间隔和额度不表示平台允许。请阅读 [BOSS 用户协议](https://www.zhipin.com/web/common/protocol/protocol-2019-09-30.html)。
